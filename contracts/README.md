# Контракт API

[openapi.yaml](openapi.yaml) задаёт маршруты, параметры и форматы ответов. Сервер и интерфейс используют его как общий контракт.

## Подключение экрана «Обзор»

1. По кнопке «Открыть демо» интерфейс отправляет `POST /api/datasets/demo` без тела. Пример ответа — [demo-dataset.json](examples/demo-dataset.json). Идентификатор набора берётся из `dataset_id`.
2. Интерфейс запрашивает `GET /api/datasets/{dataset_id}/overview`. Для моков используй [все школы](examples/demo-overview.json) и [школу S01](examples/demo-overview-s01.json). В примерах значения рассчитаны из CSV генератора с seed 42.
3. При выборе школы передай `?school_id=S01`. При сбросе фильтра убери параметр. В ответе `school_id: null` обозначает все школы. Пункты фильтра бери из `dataset.school_ids`, признак демонстрационных данных — из `dataset.is_demo`.

`student_count` — число уникальных учеников, `scores.result_count` — число пар ученик–тема. Средний балл и процент ниже порога рассчитаны по этим парам. `below_threshold_pct` уже в шкале 0–100. Порог освоения — 60 баллов, сравнение строгое. Если результатов нет, средний балл и процент равны `null`, число результатов равно 0. Для списка сложных тем сначала сортируй по точной доле ниже порога по убыванию, при равенстве — по `topic_id`. Округление для отображения выполняет интерфейс.

## Входные файлы и ошибки

`POST /api/datasets` принимает `multipart/form-data` с двумя полями-файлами `results` и `topics`. CSV используют UTF-8, запятую и заголовок. Поля, ограничения и связи описаны в [SPEC.md](../SPEC.md). Ошибка в любом файле отклоняет весь набор.

Невалидный запрос или CSV возвращает HTTP 422 с `code`, `message` и `details`. Для ошибок CSV в `details` можно указать поле загрузки, столбец и номер записи, считая заголовок первой записью. Неизвестный идентификатор возвращает HTTP 404 в том же формате.

## Темы, сравнение и план

- Тепловая карта содержит ячейки для каждой пары школа–тема в срезе, в том числе пустые. Общий список содержит все темы плана.
- Сводки учебников показывают исходные средние по выбранной теме. Для попарного сравнения разбей результаты внутри каждой школы на группы входного балла `[0, 40)`, `[40, 60)` и `[60, 100]`. Используй только группы, где в обоих учебниках по 20 или более учеников. Для каждой группы посчитай разницу среднего прироста, затем усредни разницы с весами по суммарному числу учеников двух учебников в группе. Возвращай размеры использованных выборок. Без подходящих групп сравнение имеет статус `insufficient_data`, размеры выборок равны 0, разница равна `null`. Сравнение описывает наблюдаемые результаты.
- План содержит все темы. Для каждой темы `delta_hours = proposed_hours - current_hours`, изменения сходятся с переносами, общий бюджет совпадает, соблюдаются ограничения из `topics.csv`. При отсутствии допустимых переносов возвращается `no_changes` с объяснением, одинаковыми часами до и после и пустым массивом `transfers`.
- Экспорт берёт сохранённый снимок по `plan_id` в пределах набора. CSV в UTF-8 содержит столбцы `topic_id,topic_name,current_hours,proposed_hours,delta_hours,reason` и тот же порядок строк, что в `items`.
