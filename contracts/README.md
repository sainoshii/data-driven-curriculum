# Контракт API

Перед параллельной разработкой здесь появятся `openapi.yaml` и примеры JSON для интерфейса. Владелец серверной части готовит контракт, оба разработчика сверяют его с пользовательским сценарием.

| Операция | Что должно быть определено |
| --- | --- |
| Загрузить данные | Два CSV, `dataset_id`, признак демо-данных, ошибки по строкам |
| Открыть демо | Тот же результат, что при загрузке набора |
| Получить обзор | Число учеников, доступные школы, основные показатели |
| Получить темы | Метрики по теме и школе, матрица для тепловой карты |
| Сравнить учебники | Выбранная тема, группы, средние баллы, прирост и число учеников |
| Рассчитать план | Часы до и после, изменения, основания, источники переносов и итоговые суммы |
| Экспортировать план | CSV с теми же строками и значениями, что в просмотренном плане |

До фиксации контракта нужно согласовать имена маршрутов и фильтров, формат загрузки и ошибок, границы диапазонов входного балла, минимальный размер группы и способ передачи рассчитанного плана в экспорт. Проценты в примерах API должны иметь однозначную шкалу.
