# Панель методиста

Весь интерфейс использует общую систему `src/design-system.css`: токены, адаптивную сетку, типографику, кнопки, поля, таблицы и состояния. `InputMode` оставляет короткий отклик указателя и отключает переходы при вводе с клавиатуры. В графике размеры сопоставимых групп видны постоянно. Решения, проверки и снимки — в [описании редизайна](docs/design-system/README.md).

После расчёта плана кнопка «Отчёт для методиста» рядом с CSV открывает отдельную страницу со снимком исходного, автоматического и текущего ручного планов. Она включает набор и школу, три сложные темы, сравнение учебников для выбранной темы, направления и основания переносов и проверку полного бюджета. Если ручной вариант или выбранная тема отсутствуют, это явно указано. Демо помечено как синтетические данные.

Отчёт использует рассчитанные планы без повторного POST; обзор и необязательное сравнение загружаются существующим API-клиентом для зафиксированного среза. При ошибке обзора доступен повтор, печать заблокирована; при ошибке сравнения документ показывает причину и позволяет повторить запрос. Снимок хранится в сессии вкладки отчёта: её можно обновить, но копирование ссылки в другой браузер не переносит данные. При блокировке нового окна панель показывает сообщение.

На странице отчёта нажмите «Печать / Сохранить в PDF», выберите PDF и A4 в диалоге браузера. Печатный CSS убирает панель действий, повторяет заголовки таблиц и сохраняет строки целиком. `npm test` проверяет суммы 119/119/119, расхождение бюджета, привязку к набору/школе, пометку синтетики, отсутствие данных и экранирование серверного текста. Диалог печати проверяется вручную отдельно.

На обзоре кнопки «Разобрать тему» открывают показатели выбранной темы и краткое резюме по данным API. Отсюда можно перейти к сравнению учебников и плану с той же темой и школой. В плане выбранная тема выделена. Резюме использует точные проценты из API, размер выборки и основания автоматического плана; не предсказывает рост баллов.

Сравнение «Текущий → Автоматический → Мой вариант» показывает исходные часы, автоматическое предложение и ручной сценарий отдельно. По умолчанию видны изменённые темы и выбранная тема; переключатель показывает весь план. До создания ручного варианта в его столбце стоит «—». Бюджеты приведены для полных планов независимо от фильтра строк.

После загрузки CSV появляется сводка всего набора: ученики, школы, темы и пары ученик–тема. «Начать анализ» переводит фокус к обзору. Число тем берётся из ответа getTopics; набор переключается после успешного получения обзора и списка тем. Для демонстрации есть раскрываемая подсказка «Демо за четыре шага» с переходами к разбору, сравнению и плану.

Локальный каркас на React, Vite и TypeScript. Требуется Node.js 22.12+ (или 20.19+) и npm.

```sh
cd frontend
npm install
npm run dev
```

Адрес разработки: http://127.0.0.1:5173 (если порт занят, Vite напечатает другой).

```sh
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт `dist/`. `preview` показывает готовую сборку.

«Открыть демо» выполняет `POST /api/datasets/demo`, затем запрашивает обзор с `dataset_id` из ответа. Выбор школы передаёт `school_id`, «Все школы» убирает параметр. Пункты фильтра приходят из `dataset.school_ids`.

На «Обзоре» всегда доступна форма двух файлов `results.csv` и `topics.csv`, в том числе после открытия демо. `uploadDataset` отправляет `POST /api/datasets` через FormData с полями `results` и `topics`; Content-Type с boundary устанавливает браузер. Набор переключается только после успешного получения его обзора и списка тем. Успех сбрасывает школу, выбранную тему и план; все четыре вкладки используют новый dataset_id и отметку «Загруженные данные». При ошибке старый набор и его состояние остаются открытыми, выбранные файлы можно исправить и отправить повторно. Для HTTP 422 отображаются сообщение и детали сервера (файл, строка, столбец при наличии).

`npm test` также проверяет multipart-поля без явного Content-Type, отображение деталей 422 и отметки происхождения набора.

«План часов» рассчитывается только по кнопке: `POST /api/datasets/{dataset_id}/plans`, JSON `{}` для всех школ или `{"school_id":"S01"}` для школы. Показаны бюджет до/после, все темы с изменением и основанием, источники и получатели переносов. `no_changes` показывает объяснение сервера. При смене школы предыдущий план сбрасывается, требуется новый расчёт. План сохраняется при переходе между вкладками в пределах текущего среза.

«Скачать CSV» получает файл `GET /api/datasets/{dataset_id}/plans/{plan_id}/export` для показанного сохранённого плана. До расчёта и во время смены школы экспорт отключён. При ошибке расчёт и скачивание можно повторить. Ответ расчёта после ухода со вкладки или смены среза игнорируется. Для локальных проверок сервер можно запустить с `CURRICULUM_PLANS_DB=frontend/.venv-api/plans.sqlite3`, чтобы база оставалась внутри frontend.

После расчёта доступна форма «Что если?»: две разные темы, положительное целое число часов и «Перенести». `transferPlanHours` отправляет `POST /api/datasets/{dataset_id}/plans/{plan_id}/transfers` с JSON `from_topic_id`, `to_topic_id`, `hours`, используя текущий вариант. Успех сохраняет новый `plan_id`, показывает фактические часы двух тем до/после и бюджет; отказ оставляет текущий вариант и сообщение API. Пределы часов проверяет сервер. Последовательные переносы применяются к текущему варианту. Кнопка возврата восстанавливает исходный автоматический план без нового расчёта. CSV всегда берётся по plan_id показанного варианта; имена файлов различают automatic и scenario.

Сценарий сохраняется при переходе между вкладками, сбрасывается при успешной смене школы/набора или новом автоматическом расчёте. Во время переноса расчёт, экспорт и фильтр школы заблокированы. `npm test` также проверяет сравнение 7→6/7→8, POST переноса, идентичность экспорта и сохранение варианта при 422.

`npm test` проверяет отображение плана и `no_changes`, привязку к срезу, JSON тела расчёта и URL экспорта с полученным `plan_id`.

«Учебники» получает темы через `getTopics` и сравнение через `getTextbookComparison`: `GET /api/datasets/{dataset_id}/textbook-comparison?topic_id=...` с необязательным `school_id`. Выбранная тема сохраняется при переходе между вкладками и смене школы. Сводка учебников и сопоставленные пары показаны отдельно; разница в баллах подписана «левый минус правый» и не вычисляется из округлённых средних. Размеры сопоставимых групп берутся из `comparisons`, общее число учеников — из `groups`. Для `insufficient_data` показано «Недостаточно сопоставимых данных», для `null` — «Нет данных», для нуля — 0. Данные не интерпретируются как причинное влияние учебника.

`npm test` проверяет рендеринг сводки и попарных сравнений по примеру контракта, сообщение о недостатке данных и различие между нулём и `null`.

Вкладка «Темы» использует уже открытый набор и общий фильтр школы с «Обзором». `CurriculumApi.getTopics` получает `GET /api/datasets/{dataset_id}/topics` с необязательным `school_id`. Таблица и тепловая карта сортируют темы по точной доле ниже порога (по убыванию, при равенстве — `topic_id`); `null` ставится после чисел и отображается как «Нет данных». Нулевой результат сохраняется как 0. Размер выборки — число пар ученик–тема.

Карта содержит все сочетания школ и тем выбранного среза; пропущенная ячейка обозначается «Нет данных». Цветовая шкала описывает долю ниже порога, проценты также видны в каждой ячейке. Карта прокручивается горизонтально с клавиатуры, коды тем расшифрованы в таблице и названиях столбцов. Для демо ожидается 5 × 25 ячеек, для S01 — 1 × 25. При загрузке показывается статус, при ошибке — повтор. Ответ старого запроса после смены вкладки или среза игнорируется.

`src/data/curriculum.ts` задаёт асинхронный интерфейс `CurriculumApi` и HTTP-адаптер. Ошибки соединения, HTTP и ответа показываются с кнопкой «Повторить». Запрос ограничен 15 секундами. При ошибке фильтра сохраняется предыдущий успешный срез; повтор запрашивает выбранную школу. В `src/data/mocks/` сохранены примеры контракта для справки, приложение их не использует.

Перед запуском фронтенда поднимите FastAPI из корня репозитория по основному README. Используйте стабильный Python 3.11+. Пример для Windows с Python 3.12 и локальным окружением внутри `frontend/`:

```powershell
py -3.12 -m venv frontend/.venv-api
frontend/.venv-api/Scripts/python -m pip install -r backend/requirements.txt
frontend/.venv-api/Scripts/python -B -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Vite проксирует `/api` на `http://127.0.0.1:8000` при `npm run dev`. Для развёрнутой сборки нужен серверный reverse proxy с тем же маршрутом `/api`; `dist/` сам по себе не включает FastAPI.

Проценты из `below_threshold_pct` отображаются без умножения на 100. Для отображения используется русская локаль и округление до двух знаков; темы сортируются до округления. `null` показывается как «Нет данных», отдельно от нуля. Число учеников и число результатов (пар ученик–тема) подписаны отдельно. Признак демо берётся из `dataset.is_demo`. CSV, обзор, темы, учебники и план часов подключены к API.
